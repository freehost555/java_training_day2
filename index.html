02 — TIME & SPACE ANALYSIS

Complexity Cheat Sheet

Complexity is one question: when the input becomes 10× bigger, how much more work does my program do?

Big-O Growth Rates

Notation Name Work at n = 1,00,000 Looks like Verdict
O(1) Constant 1 arr[5], map.get(k) Excellent
O(log n) Logarithmic ~17 Binary search Excellent
O(n) Linear 1,00,000 One loop Good
O(n log n) Linearithmic ~17,00,000 Arrays.sort() Acceptable
O(n²) Quadratic 10,00,00,00,000 Loop inside loop Too slow

Java Core Operations & Memory Complexity

100% Java
Operation Java Syntax JVM / Internal Implementation Time Complexity
Read by index arr[i] Direct memory offset calculation: base + i * 4 bytes O(1)
Array length arr.length Fixed constant field stored in array object header O(1)
Primitive Sort Arrays.sort(int[]) Dual-Pivot Quicksort (O(1) extra space, in-place) O(n log n)
Object Sort Arrays.sort(T[]) TimSort (stable, adaptive merge sort with run detection) O(n log n)
HashSet Lookup set.contains(x) Hash bucket lookup via hashCode() & equals() O(1) avg
HashMap Put / Get map.put(k, v) / get(k) Hash table bucket; treeifies to Red-Black tree if bucket ≥ 8 O(1) avg
Binary Search Arrays.binarySearch(...) Halves search space repeatedly on sorted array O(log n)
ArrayList Append list.add(x) Amortized constant; dynamically expands capacity by 50% O(1) amortized
ArrayList Insert / Delete list.add(idx, x) Shifts trailing elements via System.arraycopy memory block copy O(n)
Linear Scan for (int x : arr) Sequential memory traversal through contiguous blocks O(n)
03 — INTERVIEW STRATEGY

The Thinking Ladder

Never jump straight to the clever answer. Climb — and say out loud what work the previous step wasted.

Stage What you say to the interviewer Cost What it wastes
Brute force Try every possibility O(n²) Re-checks pairs it has already seen
Better Sort first, then move two pointers O(n log n) Sorting destroys original positions
Optimised Remember what I have seen in a hash map O(n) Uses extra memory — that is the trade-off
